# v0.10 — D3D11 graphics requirements

This milestone enables `XR_KHR_D3D11_enable` while creating the OpenXR instance and calls:

```text
xrGetD3D11GraphicsRequirementsKHR
```

It does not create an OpenXR session or change the game image.

## Replace

- `XR/OpenXrNativeBackend.cs`
- `XR/XrBackendState.cs`
- `PluginInfo.cs`

## Build

1. Save all files.
2. Select **Build → Rebuild Solution**.
3. Confirm:

```text
1 succeeded, 0 failed
```

4. Copy the rebuilt `MortuaryAssistantVR.dll` to:

```text
The Mortuary Assistant\BepInEx\plugins\MortuaryAssistantVR\
```

Keep `openxr_loader.dll` in the game root.

## Test

Keep:

```ini
[XR]
AttemptStartup = true
```

Connect the Quest through Virtual Desktop, start the game, wait for the main menu, and close it normally.

Expected log lines:

```text
Loading [MortuaryAssistantVR 0.10.0]
Calling xrCreateInstance with extension 'XR_KHR_D3D11_enable'
Resolve xrGetD3D11GraphicsRequirementsKHR result=0
xrGetD3D11GraphicsRequirementsKHR result=0
state=GraphicsRequirementsReady
```

Upload the complete BepInEx log.

## What the result means

- `adapterLuid` identifies the GPU adapter required by the OpenXR runtime.
- `minFeatureLevel` is the minimum Direct3D feature level required for the future session device.
- v0.11 will compare these requirements with Unity's active D3D11 device.
