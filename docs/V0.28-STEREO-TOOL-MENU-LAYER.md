# v0.28 — Stereo tool-menu layer

The tool/inventory menu is screen-space UI. Previous versions switched the
whole headset view to the desktop/cinema path while the right mouse button was
used.

v0.28 keeps true stereo rendering active and adds a third OpenXR swapchain for
UI. While the tool menu is active:

1. the left and right Unity eye cameras continue rendering the 3D world;
2. the original desktop gameplay camera is temporarily enabled so the game's
   normal screen-space tool menu is present in the desktop backbuffer;
3. the desktop backbuffer is copied into a dedicated 1600x900 OpenXR
   swapchain;
4. that swapchain is submitted as a head-locked `XrCompositionLayerQuad` in
   VIEW space, approximately 1.15 metres in front of the headset;
5. the stereo projection layer remains underneath it.

This makes the menu appear as a single floating virtual panel while the world
behind it remains stereo.

Pause and mortuary-PC interfaces continue to use the proven full
desktop/cinema fallback for now.

## Replace

- `PluginInfo.cs`
- `XR/StereoCameraRig.cs`
- `XR/OpenXrNativeBackend.cs`

No native probe rebuild is required.

## Expected startup log

```text
[XRBackend] xrCreateReferenceSpace VIEW result=0
[XRBackend] xrCreateSwapchain tool-ui result=0
[XRBackend] Tool UI swapchain ready with ... images.
```

## Expected right-mouse behavior

```text
[StereoRig] Stereo tool UI layer active; rightMouse=True, ...
```

The 3D world should remain stereo and the normal game tool menu should appear
as one head-locked floating panel.

After closing the menu:

```text
[StereoRig] Stereo tool UI layer ended; desktop gameplay camera disabled again.
```

## Limitation

The first prototype captures the complete desktop frame, not only the UI
pixels. The floating panel can therefore contain the normal desktop game view
behind the menu. Once this path is proven stable, the next refinement is to
isolate the game's UI canvas and render only the menu into the quad texture.
