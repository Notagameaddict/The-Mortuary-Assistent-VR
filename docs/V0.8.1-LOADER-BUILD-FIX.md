# v0.8.1 loader build fix

The OpenXR runtime DLL must not be loaded directly. OpenXR applications communicate with the official loader, which discovers and dispatches to the active runtime.

This replacement script avoids the Visual Studio CMake generator because the installed Visual Studio 2026 instance is not registered with CMake. It uses the MSVC compiler and NMake environment exposed by **Developer PowerShell**.

## Replace

Replace:

```text
tools/Build-OfficialOpenXRLoader.ps1
```

with the file in this package.

## Run

Open **Developer PowerShell for Visual Studio 2026**, then run:

```powershell
cd "C:\Users\Dimitri\Documents\GitHub\The-Mortuary-Assistent-VR"
Set-ExecutionPolicy -Scope Process Bypass
.\tools\Build-OfficialOpenXRLoader.ps1
```

The script first verifies that these commands exist:

```text
git
cmake
cl
nmake
```

On success, the output is:

```text
OpenXRLoaderOutput\openxr_loader.dll
OpenXRLoaderOutput\openxr_loader.dll.sha256.txt
```
