# v0.22.1 — Stereo orientation, projection and shutdown fixes

v0.22 produced the first real VR scene, but three issues remained:

1. the Unity render textures appeared vertically inverted;
2. both eyes looked nearly identical because the eye cameras used symmetric
   projection matrices;
3. the game crashed while leaving gameplay or shutting down because the native
   bridge stored raw Unity texture pointers.

This revision:

- uses a vertically flipped blit shader only for Unity eye render textures;
- copies the real per-eye OpenXR FOV angles into asymmetric Unity projection
  matrices;
- keeps COM references to both Unity eye textures in native code;
- takes a temporary COM reference during every stereo blit;
- disconnects native sources before destroying Unity textures;
- shuts down the Present callback and OpenXR backend during application quit.

## Replace

- `PluginInfo.cs`
- `Core/RuntimeBehaviour.cs`
- `XR/OpenXrHeadPose.cs`
- `XR/OpenXrNativeBackend.cs`
- `XR/HeadTrackingPatch.cs`
- `XR/StereoCameraRig.cs`
- `native/PresentHookProbe/PresentHookProbe.cpp`

## Build

1. Commit and push the updated native source.
2. Run `Build D3D11 Present Hook Probe`.
3. Replace the native probe DLL.
4. Rebuild Solution.
5. Replace the managed plugin DLL.

## Expected log

```text
Loading MortuaryAssistantVR v0.22.1
[StereoRig] Prototype eye cameras created
[StereoRig] Applied asymmetric OpenXR projections
state=StereoPrototypeRendering
```

When returning to the main menu or quitting, the log should include:

```text
[PresentHookProbe] Clear stereo sources result=0
[PresentHookProbe] Clear frame callback result=0
Shutting down XR backend.
```

## Expected result

- the scene is upright;
- left and right eyes show visibly different perspectives;
- quitting or leaving gameplay no longer crashes.

The prototype still does not copy all HDRP camera-specific settings, so visual
differences from the desktop image are still possible.
