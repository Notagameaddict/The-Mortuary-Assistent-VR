# v0.24.2 — Raycast interaction indicator and pickup fallback

The v0.24.1 log contained no `[InteractionPrompt]` lines. The previous
detector required the exact reflected full type name `PlayerInteraction`,
which did not match the IL2CPP wrapper type at runtime.

This revision no longer depends on hidden fields inside that class.

It:

- resolves `PlayerInteraction` by simple type name;
- raycasts three metres forward from the real gameplay camera;
- shows the VR hand whenever the ray hits a non-player collider;
- on left mouse click, tries parameterless methods named:
  `Interact`, `Use`, `Pickup`, `PickUp`, or `Take`;
- skips this fallback for objects whose name contains `door`, because doors
  already work normally.

## Replace

- `PluginInfo.cs`
- `XR/InteractionPromptDetector.cs`

No native rebuild is required. Keep the v0.24.1 native probe DLL.

## Expected log

```text
[InteractionPrompt] PlayerInteraction resolved
[InteractionPrompt] Ray camera resolved
[InteractionPrompt] Ray target: name='...'
[InteractionPrompt] VR hand indicator shown.
```

When the normal interaction input does not pick up a targeted object and the
fallback finds a compatible method:

```text
[InteractionPrompt] Pickup fallback invoked 'SomeType.Pickup()'
```

This is still a compatibility fallback. The target method names vary between
item types, so the resulting log is important for refining support.
