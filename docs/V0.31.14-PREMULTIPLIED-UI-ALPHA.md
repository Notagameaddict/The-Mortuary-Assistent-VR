# v0.31.14 — Premultiplied tool-UI alpha

v0.31.13 was confirmed to be running correctly, including the dual-eye
zero-disparity HUD, but the same two visual problems remained. That rules out
finite-depth binocular disparity as the main cause.

The next likely cause is alpha handling in the VirtualDesktop OpenXR
composition path.

The UI RenderTexture can contain non-zero RGB values in pixels whose alpha is
zero or almost zero. With an unpremultiplied-alpha composition layer, filtered
edge samples can leak those RGB values into the visible result. Because the
underlying scene changes indoors/outdoors, that can appear as black or blue
fringing/bars and can reduce menu contrast against nearby geometry.

v0.31.14 changes the raw tool-UI copy path to premultiplied alpha:

- completely transparent pixels become RGBA(0,0,0,0);
- all other UI pixels use RGB *= A;
- the OpenXR quad no longer sets
  XR_COMPOSITION_LAYER_UNPREMULTIPLIED_ALPHA_BIT;
- the visible cursor remains part of the same premultiplied UI texture.

## Replace

- `PluginInfo.cs`
- `XR/OpenXrNativeBackend.cs`
- `native/PresentHookProbe/PresentHookProbe.cpp`

## Native rebuild required

Run `Build D3D11 Present Hook Probe`, replace
`MortuaryAssistantVR.PresentHookProbe.dll`, then rebuild the managed project
and replace `MortuaryAssistantVR.dll`.
