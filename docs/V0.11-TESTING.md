# v0.11 — Unity D3D11 native bridge

This milestone obtains Unity's existing `ID3D11Device` through Unity's native plug-in interface and compares its GPU adapter LUID and feature level with the requirements reported by OpenXR.

It does not create an OpenXR session.

## Why a native bridge is required

Unity's managed API does not expose the active `ID3D11Device`. Unity's low-level native plug-in interface provides `IUnityGraphicsD3D11::GetDevice()` for this purpose.

## Replace/add C# files

Replace:

- `XR/OpenXrNativeBackend.cs`
- `XR/XrBackendState.cs`
- `PluginInfo.cs`

Add:

- `XR/UnityD3D11Bridge.cs`

## Add the native build workflow

Copy:

```text
.github/workflows/build-unity-d3d11-bridge.yml
```

Commit and push it to GitHub.

Run:

```text
Actions → Build Unity D3D11 Bridge → Run workflow
```

Download the artifact:

```text
mortuary-assistant-vr-unity-d3d11-bridge
```

Extract:

```text
MortuaryAssistantVR.UnityD3D11Bridge.dll
```

## Install the native bridge

Place the native bridge in:

```text
The Mortuary Assistant_Data\Plugins\x86_64\
```

Create `x86_64` if it does not exist.

Do not replace UnityPlayer.dll and do not put the bridge in System32.

Keep the Khronos `openxr_loader.dll` in the game root.

## Build the managed plugin

Rebuild the solution, then copy `MortuaryAssistantVR.dll` to:

```text
BepInEx\plugins\MortuaryAssistantVR\
```

Keep:

```ini
[XR]
AttemptStartup = true
```

## Expected log

```text
Loading [MortuaryAssistantVR 0.11.0]
[UnityD3D11Bridge] Native result=0
D3D11 comparison: adapterMatches=True, featureLevelMatches=True
state=UnityGraphicsDeviceReady
```

If the bridge returns result `2`, Unity did not call `UnityPluginLoad`; verify that the native DLL is in `The Mortuary Assistant_Data\Plugins\x86_64` before the game starts.
