# v0.19 — Head-locked cinema quad

v0.18 proved that the real game image reaches the headset, but submitting a
flat desktop image as a stereo projection layer gives incorrect placement and
projection.

This milestone submits the desktop image as an OpenXR quad layer instead:

- 2.0 metres in front of the LOCAL origin;
- 2.4 metres wide;
- 1.35 metres high;
- visible to both eyes;
- one shared texture, so it remains monoscopic.

This should make the image look like a stable virtual cinema screen rather
than a distorted world projection.

## Replace

- `PluginInfo.cs`
- `XR/OpenXrNativeBackend.cs`
- `XR/XrBackendState.cs`

No native probe rebuild is required. Keep the v0.18 native DLL.

## Test

1. Rebuild Solution.
2. Copy the rebuilt `MortuaryAssistantVR.dll`.
3. Connect Virtual Desktop.
4. Start the game.

Expected result:

- a centred flat game screen approximately two metres ahead;
- no red/blue test pattern;
- no projection-layer warping.

Expected log:

```text
Loading MortuaryAssistantVR v0.19.0
Test frame 1: wait=0, begin=0, end=0
state=CinemaQuadRendering
status='OpenXR head-locked cinema quad is active.'
```

## Important limitation

This is not true stereoscopic VR yet. Rendering two head-tracked Unity cameras
requires a safe Unity render-thread bridge. The native Present loop cannot
directly call Unity camera APIs. This quad milestone first fixes placement and
provides a stable visible baseline before adding that bridge.
