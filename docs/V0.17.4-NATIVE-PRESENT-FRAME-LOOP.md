# v0.17.4 — Native Present-driven OpenXR frame loop

Managed Unity callbacks were either unavailable or never invoked in this
IL2CPP game build. The native Present hook is known to run continuously,
because it captured Unity's real D3D11 device.

This revision adds a callback export to the native probe:

```text
MAVR_SetPresentFrameCallback
```

The hook invokes the managed OpenXR frame function from every real
`IDXGISwapChain::Present()` call. A thread-local reentrancy guard prevents
recursive callback execution.

## Managed files to replace

- `PluginInfo.cs`
- `XR/D3D11PresentHookProbe.cs`
- `XR/XrBackendManager.cs`

Use the v0.17.2 versions of the other managed files.

## Native source to replace

- `native/PresentHookProbe/PresentHookProbe.cpp`

Commit and push the native source, then run:

```text
Actions → Build D3D11 Present Hook Probe → Run workflow
```

Download and replace the native probe DLL in the same location that currently
works.

## Then

1. Rebuild Solution.
2. Copy the rebuilt managed DLL.
3. Connect Virtual Desktop and the headset.
4. Start the game.

Expected log:

```text
Loading MortuaryAssistantVR v0.17.4
Set frame callback result=0
First native Present frame callback observed
Test frame 1: wait=0, begin=0, end=0
Test frame 2: wait=0, begin=0, end=0
```

Expected headset result:

- left eye red;
- right eye blue.

## Safety

The callback executes on Unity's D3D11 Present thread. If the game freezes or
crashes, set `AttemptStartup = false` and restore v0.17.2.
