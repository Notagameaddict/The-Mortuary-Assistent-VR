# v0.31.2 — Sharp and input-aligned stereo tool UI

The v0.31.1 log confirms that CircleRet capture is now working:

```text
[ToolMenuUI] CircleRet visible.
[StereoRig] InGameUI Canvas redirected directly to transparent tool UI RenderTexture.
[StereoRig] CircleRet stereo UI capture active.
```

No OpenXR frame errors occur during these menu sessions.

The remaining symptoms are consistent with a pixel-space mismatch:

- the normal game backbuffer is 2560x1440;
- v0.31.1 redirected the Canvas to a 1600x900 RenderTexture;
- the OpenXR UI swapchain was also 1600x900.

Unity UI/EventSystem coordinates are based on screen pixels. Redirecting the
Canvas to a lower-resolution target can make the visual UI and the original
mouse/radial hit coordinates disagree. It also forces an extra downsample and
upscale, which makes text/icons soft in the headset.

v0.31.2 changes both the Unity UI RenderTexture and OpenXR UI swapchain to
2560x1440, matching the game's logged desktop viewport.

It also:

- forces the UI camera to a full 16:9 rect;
- disables HDR, MSAA, and dynamic resolution on the UI-only camera;
- makes the OpenXR panel slightly smaller and closer to increase angular pixel
  density;
- logs both `Screen.width/height` and the capture resolution when the menu
  opens.

## Replace

- `PluginInfo.cs`
- `XR/StereoCameraRig.cs`
- `XR/OpenXrNativeBackend.cs`

No native PresentHookProbe rebuild is required. Keep the v0.31 native probe.

[StereoRig] InGameUI Canvas redirected directly to transparent tool UI RenderTexture; screen=2560x1440, capture=2560x1440.

If `screen=` reports a different resolution, use that value for the next
