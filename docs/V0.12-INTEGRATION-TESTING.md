# v0.12 — Present-hook integration

This milestone loads and starts `MortuaryAssistantVR.PresentHookProbe.dll` from the managed BepInEx plug-in.

## Replace/add

Replace:

- `PluginInfo.cs`
- `Core/RuntimeBehaviour.cs`
- `XR/OpenXrNativeBackend.cs`
- `XR/XrBackendManager.cs`
- `XR/XrBackendState.cs`

Add:

- `XR/D3D11PresentHookProbe.cs`

Keep the already-built native file:

```text
MortuaryAssistantVR.PresentHookProbe.dll
```

in the game root, beside:

```text
The Mortuary Assistant.exe
```

Putting it only in the BepInEx plug-in folder may not be sufficient for Windows DLL resolution.

## Test

1. Rebuild Solution.
2. Copy the rebuilt `MortuaryAssistantVR.dll`.
3. Keep `[XR] AttemptStartup = true`.
4. Start the game without manually starting SteamVR.
5. Wait at the main menu for approximately ten seconds.
6. Close the game and upload the complete BepInEx log.

Expected progression:

```text
Loading [MortuaryAssistantVR 0.12.0]
[PresentHookProbe] Install result=0
state=WaitingForUnityGraphicsDevice
[PresentHookProbe] Query result=2
```

After the first real `Present` call, the expected result changes to:

```text
[PresentHookProbe] Query result=0
Captured Unity D3D11 device=0x...
Present-hook comparison: adapterMatches=True, featureLevelMatches=True
state=UnityGraphicsDeviceReady
```

The query can report result `2` for several early frames. That is normal. The managed code polls every Unity update until a device is captured.

This milestone still does not call `xrCreateSession`.
