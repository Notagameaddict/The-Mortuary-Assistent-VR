# v0.31.8 — Suppress InGameUI root CanvasRenderer

v0.31.7 is a major improvement:

- the tool menu is sharp;
- selection works everywhere;
- the normal stereo world is visible behind most of the menu;
- only residual black/blue regions remain at the lower-left and right edges.

The latest log confirms the intended capture topology is stable:

```text
InGameUI Canvas root + CircleRet subtree isolated on capture layer 30
Rsystem remains excluded
```

At this point the only capture-layer object outside CircleRet itself is the
`InGameUI` root. The root must remain on layer 30 because it owns the Canvas,
but a `CanvasRenderer`/Graphic attached directly to that root can still draw
edge/vignette/background pixels.

v0.31.8 keeps the InGameUI Canvas root on layer 30, but temporarily sets
`cull = true` on any `CanvasRenderer` attached directly to the InGameUI root.
CircleRet's own CanvasRenderers remain untouched.

Original cull states are restored as soon as the tool menu closes.

## Replace

- `PluginInfo.cs`
- `XR/StereoCameraRig.cs`

No native probe rebuild is required. Keep the v0.31.4 PresentHookProbe DLL.

## Expected log

```text
[StereoRig] Suppressed ... CanvasRenderer(s) attached directly to InGameUI root during tool UI capture.
[StereoRig] InGameUI Canvas root + CircleRet subtree isolated ... root CanvasRenderer output is suppressed.
```

If the first line reports `0 CanvasRenderer(s)`, the residual edge color is not
coming from the InGameUI root Graphic and the next step should be cropping the
OpenXR quad to the actual CircleRet bounds.
