# v0.5 OpenXR runtime probe

This milestone detects the active Windows OpenXR runtime and looks for an application-local `openxr_loader.dll`.

It does not create an OpenXR instance or session yet and does not enable headset tracking or stereoscopic rendering.

## Replace

- `Config/ModConfig.cs`
- `Core/RuntimeBehaviour.cs`
- `PluginInfo.cs`

## Add

- `XR/OpenXrRuntimeProbe.cs`

Keep:

- `XR/XrRigBootstrap.cs`
- all diagnostics files

## Build and install

1. Rebuild the solution.
2. Confirm `1 succeeded, 0 failed`.
3. Copy the new DLL to:

```text
BepInEx/plugins/MortuaryAssistantVR/
```

4. Overwrite the previous DLL.

## Test with Virtual Desktop

1. Start Virtual Desktop and connect the Quest.
2. Make sure Virtual Desktop is selected as the active OpenXR runtime.
3. Start the game normally.
4. Load a shift briefly.
5. Exit normally.
6. Open `BepInEx/LogOutput.log`.

The log should contain:

```text
Loading [MortuaryAssistantVR 0.5.0]
=== OpenXR Runtime Probe begin
[OpenXR] Active runtime manifest
[OpenXR] Runtime library
[OpenXR] Runtime library exists
[OpenXR] Loader candidate
=== OpenXR Runtime Probe end
```

Upload the log. Do not manually download random copies of `openxr_loader.dll`; the next build will use a controlled loader source after the runtime path is confirmed.
