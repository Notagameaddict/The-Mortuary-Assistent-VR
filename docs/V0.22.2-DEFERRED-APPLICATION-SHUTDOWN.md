# v0.22.2 — Do not shut OpenXR down during scene startup

The v0.22.1 log showed:

```text
Test frame 1 ...
Shutting down XR backend.
Clear frame callback result=0.
```

This happened before the MainMenu scene finished loading. The newly added
`RuntimeBehaviour.OnDestroy()` callback was invoked by Unity's object/scene
lifecycle and incorrectly treated that event as application shutdown.

As a result, the OpenXR instance and session were destroyed immediately.
Later, the Mortuary scene created the stereo cameras, but there was no active
backend left to submit them.

This revision:

- removes shutdown from `OnDestroy()`;
- keeps shutdown only in `OnApplicationQuit()`;
- calls `xrEndSession()` only if the session is actually running.

## Replace

- `PluginInfo.cs`
- `Core/RuntimeBehaviour.cs`
- `XR/OpenXrNativeBackend.cs`

No native probe rebuild is required. Keep the v0.22.1 native DLL.

## Expected log

Startup should no longer contain an early:

```text
Shutting down XR backend.
```

In the Mortuary scene, expect:

```text
[StereoRig] Prototype eye cameras created
[PresentHookProbe] Set stereo sources result=0
state=StereoPrototypeRendering
```

Only when the application really closes should the shutdown lines appear.
