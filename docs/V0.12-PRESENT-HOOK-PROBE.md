# v0.12 — D3D11 Present-hook probe

The previous Unity native plug-in approach could load the DLL, but Unity did not call `UnityPluginLoad`, so no `IUnityInterfaces` pointer was available.

This diagnostic milestone uses a different method:

1. create a temporary D3D11 swap chain to obtain the process-wide `IDXGISwapChain::Present` function address;
2. install a MinHook detour on `Present`;
3. capture the actual D3D11 device from the first real game swap chain that presents;
4. expose the device pointer, adapter LUID, and feature level to C#.

This version is diagnostic only. It does not call `xrCreateSession`.

## Files

Add:

- `.github/workflows/build-present-hook-probe.yml`
- `native/PresentHookProbe/PresentHookProbe.cpp`
- `src/MortuaryAssistantVR/XR/D3D11PresentHookProbe.cs`

## Build the native probe

Commit and push the workflow and native source, then run:

```text
Actions → Build D3D11 Present Hook Probe → Run workflow
```

Download:

```text
mortuary-assistant-vr-present-hook-probe
```

Copy:

```text
MortuaryAssistantVR.PresentHookProbe.dll
```

to the game root beside the executable.

## Important integration note

The C# backend still needs a small lifecycle change:

- install the hook during backend initialization;
- do not immediately fail when no device has been captured;
- poll the probe after the first rendered frames or when the MainMenu scene loads.

Do not replace the existing v0.11 native bridge yet. First build and install this probe. The next revision will wire the polling into `RuntimeBehaviour`.
