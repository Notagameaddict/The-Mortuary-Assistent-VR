# v0.23 — Pause-menu fallback and visible VR cursor

The stereo eye cameras render the 3D world correctly, but Unity
Screen Space Overlay UI is drawn directly to the desktop backbuffer. It is not
included in the two eye render textures. That is why the pause menu was
missing.

This revision automatically switches to the stable desktop/cinema path while
`Time.timeScale == 0`. The normal desktop frame contains the game's pause menu
and other overlay UI. Resuming restores the stereo eye textures.

The native blit shaders also draw a high-contrast cursor cross at the current
Windows cursor position whenever the operating-system cursor is visible.

## Replace

- `PluginInfo.cs`
- `XR/HeadTrackingPatch.cs`
- `XR/StereoCameraRig.cs`
- `native/PresentHookProbe/PresentHookProbe.cpp`

## Native rebuild required

1. Commit and push the updated native source.
2. Run `Build D3D11 Present Hook Probe`.
3. Replace `MortuaryAssistantVR.PresentHookProbe.dll`.
4. Rebuild Solution.
5. Replace `MortuaryAssistantVR.dll`.

## Expected behavior

During gameplay:

- true stereo world rendering remains active;
- when the game exposes the mouse cursor, a white cursor cross with black
  outline is visible in the headset.

When pausing:

```text
[StereoRig] Pause detected; using desktop/cinema fallback so overlay UI is visible.
```

The pause menu should become visible. After resuming:

```text
[StereoRig] Gameplay resumed; stereo eye textures restored.
```

## Judder

This revision does not yet solve the remaining small judder. The log shows the
OpenXR frame loop itself is stable. The likely source is timing mismatch
between Unity's two off-screen HDRP cameras and the native Present-driven
OpenXR submission. That requires a dedicated synchronization milestone after
UI visibility is confirmed.
