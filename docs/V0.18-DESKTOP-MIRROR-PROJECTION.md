# v0.18 — First game image in the headset

This milestone replaces the red/blue clear with a native shader blit from
Unity's current DXGI backbuffer into both OpenXR eye swapchains.

The same desktop image is submitted to both eyes. This is intentionally
monoscopic and is not yet head-tracked stereo rendering.

## Replace managed files

- `PluginInfo.cs`
- `XR/D3D11PresentHookProbe.cs`
- `XR/OpenXrNativeBackend.cs`

Keep the v0.17.4.1 manager and native Present callback integration.

## Replace native and workflow files

- `native/PresentHookProbe/PresentHookProbe.cpp`
- `.github/workflows/build-present-hook-probe.yml`

The workflow now links `d3dcompiler.lib`.

## Build

1. Commit and push the native source and workflow.
2. Run a new `Build D3D11 Present Hook Probe` workflow.
3. Download and replace the native probe DLL.
4. Rebuild Solution.
5. Copy the managed DLL.
6. Connect Virtual Desktop and start the game.

## Expected result

Both eyes should show the desktop game image. It may look flat, incorrectly
scaled, or uncomfortable because both eyes receive the same image.

Expected log:

```text
Loading MortuaryAssistantVR v0.18.0
First native Present frame callback observed
Test frame 1: wait=0, begin=0, end=0
```

If the blit fails, the log includes a native result code and HRESULT.

## Safety

This prototype temporarily changes D3D11 pipeline state during Present and
restores the primary state used by the blit. If the game crashes or rendering
breaks, restore v0.17.4.1 and set `AttemptStartup = false`.
