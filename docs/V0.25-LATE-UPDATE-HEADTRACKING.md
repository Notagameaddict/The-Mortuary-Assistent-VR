# v0.25 — LateUpdate head tracking

The OpenXR frame loop is stable at roughly the headset refresh cadence, but
the Unity head transform was being updated from `MFPP.Player.Update`.

Unity renders cameras after `LateUpdate`, so applying the latest headset pose
there reduces the age of the pose used by the two off-screen eye cameras.

This revision:

- keeps interaction and pause-state work in `MFPP.Player.Update`;
- patches `MFPP.Player.LateUpdate` when available;
- applies rotation, position, and eye projection matrices in LateUpdate;
- falls back to Update on game builds without a LateUpdate method.

## Replace

- `PluginInfo.cs`
- `XR/HeadTrackingPatch.cs`

No native probe rebuild is required.

## Expected log

```text
[HeadTracking] Patched MFPP.Player.Update for interaction/presentation maintenance.
[HeadTracking] Patched MFPP.Player.LateUpdate for late head-pose application.
[HeadTracking] Late pose 1: ...
```

## Expected effect

Head-motion judder should be reduced because the eye cameras use a newer
headset pose immediately before Unity renders them.

This is still not true compositor late-latching. If some judder remains, the
next step is to tag each rendered eye frame with the exact OpenXR pose used for
that Unity render and submit the matching projection pose to the compositor.
