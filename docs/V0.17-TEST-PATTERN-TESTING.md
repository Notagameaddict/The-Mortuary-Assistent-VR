# v0.17 — First visible OpenXR projection layer

This milestone is intended to produce the first visible headset image.

For every renderable frame it:

1. calls `xrLocateViews`;
2. acquires one image from each eye swapchain;
3. waits for each image;
4. clears the left-eye texture red and the right-eye texture blue through the native D3D11 helper;
5. releases both images;
6. submits one `XrCompositionLayerProjection` with two views.

It does not render the game camera yet.

## Replace/add managed files

Replace:

- `PluginInfo.cs`
- `XR/OpenXrNativeBackend.cs`
- `XR/XrBackendState.cs`
- `XR/D3D11PresentHookProbe.cs`

Keep:

- `XR/OpenXrSwapchainImageSet.cs`

## Rebuild the native probe

The native probe has a new export:

```text
MAVR_ClearD3D11Texture
```

Copy the updated:

- `native/PresentHookProbe/PresentHookProbe.cpp`

Commit and push it, then run:

```text
Actions → Build D3D11 Present Hook Probe → Run workflow
```

Download and replace:

```text
MortuaryAssistantVR.PresentHookProbe.dll
```

in the game root.

## Build and test

1. Rebuild Solution.
2. Copy the new managed `MortuaryAssistantVR.dll`.
3. Keep `[XR] AttemptStartup = true`.
4. Connect Virtual Desktop and the headset.
5. Start the game and remain at the main menu.
6. The expected headset result is a solid red left eye and solid blue right eye.
7. Close the game and upload `LogOutput.log`.

Expected log:

```text
Loading [MortuaryAssistantVR 0.17.0]
Resolve xrAcquireSwapchainImage result=0
Resolve xrWaitSwapchainImage result=0
Resolve xrReleaseSwapchainImage result=0
Resolve xrLocateViews result=0
Test frame 1: wait=0, begin=0, end=0
state=TestPatternRendering
```

## Recovery

This milestone writes to native GPU resources. If the game crashes or the headset becomes unstable:

```ini
[XR]
AttemptStartup = false
```

Restore the v0.16 managed DLL and previous native probe DLL.
