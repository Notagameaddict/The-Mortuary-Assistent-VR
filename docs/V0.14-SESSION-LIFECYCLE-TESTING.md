# v0.14 — Session lifecycle and empty frame loop

This milestone adds:

- OpenXR event polling;
- LOCAL reference-space creation;
- `xrBeginSession` after `XR_SESSION_STATE_READY`;
- an empty `xrWaitFrame` / `xrBeginFrame` / `xrEndFrame` loop;
- graceful handling of `STOPPING`, `LOSS_PENDING`, and `EXITING`.

No swapchains or composition layers are created yet. Every submitted frame has zero layers.

## Replace

- `PluginInfo.cs`
- `XR/OpenXrNativeBackend.cs`
- `XR/XrBackendState.cs`

No native Present-hook rebuild is required.

## Test

1. Rebuild Solution.
2. Copy the rebuilt `MortuaryAssistantVR.dll`.
3. Keep the Present-hook DLL in the game root.
4. Keep `[XR] AttemptStartup = true`.
5. Connect Virtual Desktop and the headset before starting the game.
6. Start the game and remain at the main menu for 10–15 seconds.
7. Close the game and upload the complete BepInEx log.

Expected progression:

```text
Loading [MortuaryAssistantVR 0.14.0]
xrCreateSession result=0
xrCreateReferenceSpace result=0
Session state changed: READY
xrBeginSession result=0
OpenXR session is running
Empty frame 1: wait=0, begin=0, end=0
state=FrameLoopActive
```

The runtime may also report `SYNCHRONIZED`, `VISIBLE`, and `FOCUSED`.

## Important safety note

This version calls `xrWaitFrame` from Unity's managed update loop. It is a diagnostic milestone and may affect game timing. If the game freezes or crashes, set:

```ini
[XR]
AttemptStartup = false
```

and preserve the log or crash dump.
