# v0.20 — Head rotation tracking

This milestone keeps the stable v0.19 cinema quad and adds the first
head-tracking bridge to the Unity gameplay camera hierarchy.

The native OpenXR frame loop stores the latest pose returned by
`xrLocateViews`. A Harmony postfix on the game's existing
`MFPP.Player.Update` method runs on Unity's main thread and applies the
headset rotation to:

```text
MortuaryAssistantVR_Head
```

Only rotation is applied. Positional tracking and stereoscopic Unity
rendering remain disabled.

## Replace

- `PluginInfo.cs`
- `Core/RuntimeBehaviour.cs`
- `XR/OpenXrNativeBackend.cs`
- `XR/XrBackendManager.cs`

## Add

- `XR/OpenXrHeadPose.cs`
- `XR/HeadTrackingPatch.cs`

No native probe rebuild is required. Keep the v0.18 native DLL.

## Build and test

1. Rebuild Solution.
2. Copy the rebuilt managed DLL.
3. Connect Virtual Desktop.
4. Start the game and enter the Mortuary scene.
5. Move your head slowly left, right, up, and down.

Expected log:

```text
Loading MortuaryAssistantVR v0.20.0
[HeadTracking] Patched MFPP.Player.Update.
[HeadTracking] XR head transform found.
[HeadTracking] Applied pose 1: ...
```

## Expected behaviour

The cinema screen remains visible as the safe output path. In gameplay, the
Unity camera hierarchy should now receive headset rotation. Depending on the
game's own mouse-look script, rotation may be overwritten, doubled, inverted,
or jittery. The log will establish whether the main-thread bridge works before
we disable the game's camera rotation or add position tracking.
