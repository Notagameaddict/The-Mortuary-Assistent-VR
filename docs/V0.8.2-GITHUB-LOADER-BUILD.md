# v0.8.2 — Build the official loader with GitHub Actions

This replaces the local CMake/MSVC/NMake procedure.

Your computer no longer needs a working local C++ command-line environment. GitHub builds the loader on a hosted Windows machine using the official Khronos OpenXR SDK source.

## Install the workflow

Copy:

```text
.github/workflows/build-openxr-loader.yml
```

to the same path in the repository.

Commit and push the file to GitHub.

## Run the workflow

1. Open the repository on GitHub.
2. Select **Actions**.
3. Select **Build Official OpenXR Loader**.
4. Select **Run workflow**.
5. Wait until the run has a green check mark.
6. Open the completed workflow run.
7. Under **Artifacts**, download:

```text
openxr-loader-windows-x64-1.1.62
```

8. Extract the downloaded ZIP.

It contains:

```text
openxr_loader.dll
openxr_loader.dll.sha256.txt
```

## Install the loader

Copy `openxr_loader.dll` to:

```text
The Mortuary Assistant\BepInEx\plugins\MortuaryAssistantVR\
```

Do not place it in `System32`.

## Test 1: loader only

Keep:

```ini
[XR]
AttemptStartup = false
```

Rebuild the C# plugin as v0.8.0, copy the plugin DLL, and run the game.

Expected log state:

```text
StartupDisabled
```

## Test 2: OpenXR instance

After Test 1 succeeds:

1. Close the game.
2. Connect the Quest through Virtual Desktop.
3. Set:

```ini
[XR]
AttemptStartup = true
```

4. Start the game.

Expected:

```text
xrCreateInstance result=0
state=InstanceCreated
```

If the game crashes or the result is non-zero, restore `AttemptStartup = false` and upload the complete BepInEx log.
