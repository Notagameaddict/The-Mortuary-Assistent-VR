# v0.24.6 — Stereo-aligned interaction reticle

The v0.24.5 reticle was drawn at UV (0.5, 0.5) in both eye textures. That is
not the same visual direction when OpenXR uses asymmetric per-eye projection
frustums.

For the current runtime, the forward direction is roughly:

```text
left eye  U ~= 0.62
right eye U ~= 0.38
```

Drawing both markers at 0.5 therefore creates binocular disparity and the user
sees two reticles.

This revision projects the common head-forward ray into each eye's actual
OpenXR FOV. The shader receives a separate UV coordinate for the left and
right eye, so the two marks should fuse into one apparent reticle.

## Replace

- `PluginInfo.cs`
- `XR/D3D11PresentHookProbe.cs`
- `XR/InteractionPromptDetector.cs`
- `native/PresentHookProbe/PresentHookProbe.cpp`

## Native rebuild required

1. Commit and push.
2. Run `Build D3D11 Present Hook Probe`.
3. Replace the native probe DLL.
4. Rebuild Solution.
5. Replace `MortuaryAssistantVR.dll`.

Expected log when an interaction target becomes active:

```text
[InteractionPrompt] VR reticle shown:
leftUv=(..., ...), rightUv=(..., ...)
```

The left and right U values should be different. That difference is intentional
and compensates for the asymmetric OpenXR eye frustums.
