# v0.12.1 — Managed update-loop diagnostics

This revision determines whether Unity calls the injected `RuntimeBehaviour.Update()` method and whether the managed plug-in polls the native Present-hook probe.

## Replace

- `PluginInfo.cs`
- `Core/RuntimeBehaviour.cs`
- `XR/OpenXrNativeBackend.cs`
- `XR/XrBackendManager.cs`
- `XR/D3D11PresentHookProbe.cs`

No native DLL rebuild is required.

## Test

1. Rebuild Solution.
2. Copy the rebuilt `MortuaryAssistantVR.dll`.
3. Keep `MortuaryAssistantVR.PresentHookProbe.dll` in the game root.
4. Start the game and remain at the main menu for at least ten seconds.
5. Close the game and upload `LogOutput.log`.

Expected diagnostics when Unity invokes `Update()`:

```text
Loading [MortuaryAssistantVR 0.12.1]
[XRBackend] First managed update poll observed.
[XRBackend] Present-hook poll attempt 1.
[PresentHookProbe] Query result=...
[RuntimeBehaviour] Update heartbeat: count=...
```

Interpretation:

- No `First managed update poll observed`: Unity is not invoking the injected `Update()` method.
- Polling with `Query result=2`: the update loop works, but the native hook has not captured a real game swap chain.
- `Query result=0`: the device was captured and can be validated against OpenXR.
