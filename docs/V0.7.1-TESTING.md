# v0.7.1 XR backend lifetime fix

This update prevents the XR backend from being disposed during normal scene transitions.

## Replace

- `Core/RuntimeBehaviour.cs`
- `XR/XrBackendManager.cs`
- `PluginInfo.cs`

Keep all other v0.7 files.

## What changed

- Removed `RuntimeBehaviour.OnDestroy()` backend shutdown.
- Backend initialization is now guarded and only attempted once.
- Scene changes no longer dispose or recreate the backend.
- Backend state remains available when the `Mortuary` scene loads.

## Build and install

1. Rebuild the solution.
2. Confirm `1 succeeded, 0 failed`.
3. Copy the rebuilt DLL to:

```text
BepInEx/plugins/MortuaryAssistantVR/
```

4. Keep:

```ini
[XR]
AttemptStartup = false
```

## Test

1. Start the game.
2. Enter the main menu.
3. Load a playable shift.
4. Exit normally.
5. Open `BepInEx/LogOutput.log`.

Expected:

```text
Loading [MortuaryAssistantVR 0.7.1]
=== XR Backend initialization begin
state=LoaderUnavailable
=== XR Backend initialization end
```

There should be no early:

```text
Shutting down XR backend.
```

When the `Mortuary` scene loads, the log should still show:

```text
[XRBackend] Current state: name='OpenXR Native', state=LoaderUnavailable
```

Upload the resulting log.
