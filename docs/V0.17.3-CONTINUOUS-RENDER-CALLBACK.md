# v0.17.3 — Continuous OpenXR frame submission

v0.17.2 successfully submitted one valid projection frame:

```text
Test frame 1: wait=0, begin=0, end=0
```

but no later test frames appeared. The scene-load fallback caused the single
frame; Unity's injected `Update()` method was not a reliable render callback.

This revision registers:

```csharp
Application.onBeforeRender
```

The callback continuously drives the OpenXR frame sequence. Ordinary
`Update()` calls only poll device availability and OpenXR events.

## Replace

- `PluginInfo.cs`
- `Core/RuntimeBehaviour.cs`
- `XR/OpenXrNativeBackend.cs`
- `XR/XrBackendManager.cs`

No native Present-hook rebuild is required. Keep the v0.17.1 native DLL.
