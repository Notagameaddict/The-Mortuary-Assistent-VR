# v0.27 — Full-screen UI fallback for the mortuary PC

v0.26 disables the original desktop gameplay camera during stereo rendering to
reduce HDRP load. That improves smoothness, but full-screen screen-space UI
such as the mortuary computer interface is not rendered into the two off-screen
eye textures.

The log shows the player looking at `CompWall`, followed by a pause-style
fallback transition. It also shows rapid fallback/resume oscillation and one
`Stereo blit failed ... result=20`, so the old `timeScale == 0` test is not
stable enough for the computer interface.

v0.27 treats either of these as a full-screen UI signal:

- `Time.timeScale == 0`;
- Unity's mouse cursor is visible.

It also keeps the desktop/cinema fallback active for 0.75 seconds after the
last UI signal. This debounce prevents the PC interface from bouncing between
stereo and desktop output while it opens or closes.

The original gameplay camera is re-enabled while fallback is active, so
screen-space UI reaches the desktop backbuffer. When the UI closes, the
desktop camera is disabled again and stereo rendering resumes.

The reset path now uses Unity's overloaded null comparison for the source
camera, avoiding the `Behaviour.set_enabled` NullReference seen when returning
to the main menu.

## Replace

- `PluginInfo.cs`
- `XR/StereoCameraRig.cs`

No native probe rebuild is required.

## Expected log when opening the mortuary PC

```text
[StereoRig] Unity cursor visibility bridge resolved for screen-space UI detection.
[StereoRig] UI fallback active; paused=..., cursorVisible=True. Using desktop/cinema output for screen-space UI.
```

When the computer interface closes:

```text
[StereoRig] UI fallback ended; stereo eye textures restored.
```
