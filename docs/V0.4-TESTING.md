# v0.4 XR rig bootstrap

This milestone creates an identity transform hierarchy around the existing gameplay camera:

```text
Player
└── CamHelper
    └── MortuaryAssistantVR_XROrigin
        └── MortuaryAssistantVR_Head
            └── Camera
```

It does **not** start OpenXR, render stereoscopically, or read headset tracking yet. Because the new transforms are identity transforms, normal desktop camera behavior should remain unchanged.

## Replace

- `Config/ModConfig.cs`
- `Core/RuntimeBehaviour.cs`
- `PluginInfo.cs`

## Add

- `XR/XrRigBootstrap.cs`

Keep the existing diagnostics files.

## Build and install

1. Rebuild the solution.
2. Confirm `1 succeeded, 0 failed`.
3. Copy the new DLL to:

```text
BepInEx/plugins/MortuaryAssistantVR/
```

4. Overwrite the previous DLL.

## Test

1. Start the game normally without starting VR.
2. Load a playable shift.
3. Check that the camera still looks and moves normally.
4. Walk, look around, interact with one object, and pause/unpause.
5. Exit normally.
6. Open `BepInEx/LogOutput.log`.

The log should contain:

```text
Loading [MortuaryAssistantVR 0.4.0]
=== XR Rig Bootstrap begin
XR rig hierarchy created
[XRRig] Origin path
[XRRig] Head path
[XRRig] Camera path after bootstrap
=== XR Rig Bootstrap end
```

The expected camera path after bootstrap is:

```text
Player/CamHelper/MortuaryAssistantVR_XROrigin/MortuaryAssistantVR_Head/Camera
```

Upload the log and report whether normal camera movement remained unchanged.
