# v0.31 — CircleRet stereo UI capture

The v0.30.1 probe established that the right-mouse tool menu is:

```text
InGameUI/Rsystem/CircleRet
```

and that the hierarchy becomes inactive when the menu closes.

v0.31 removes the diagnostic snapshots and uses the real `CircleRet`
visibility as the menu signal.

## Rendering path

While CircleRet is visible:

1. normal left/right VR eye cameras continue rendering the world;
2. the original desktop world camera stays disabled;
3. `InGameUI`'s existing Canvas is temporarily redirected from its normal
   screen-space mode to a dedicated transparent 1600x900 RenderTexture;
4. a UI-only camera renders Unity UI layer 5 into that texture with transparent
   background;
5. the texture is copied directly into the OpenXR tool-UI swapchain;
6. the OpenXR quad uses source-alpha blending, so only UI pixels should appear
   above the true stereo world.

When CircleRet closes, the original Canvas render mode/world camera are
restored immediately.

The implementation uses `GetComponent("Canvas")` rather than
`GetComponent(System.Type)` to avoid the IL2CPP System.Type mismatch.

## Native rebuild required

The PresentHookProbe gets a new export:

```text
MAVR_BlitSourceTexture
```

Therefore run `Build D3D11 Present Hook Probe`, replace the native probe DLL,
then rebuild the managed solution and replace `MortuaryAssistantVR.dll`.

## Expected log

```text
[ToolMenuUI] CircleRet visible.
[StereoRig] InGameUI Canvas redirected to transparent tool UI RenderTexture
[StereoRig] CircleRet stereo UI capture active.
```

On menu close:

```text
[ToolMenuUI] CircleRet hidden.
[StereoRig] CircleRet stereo UI capture ended.
```

If the Canvas cannot be redirected, the log will explicitly report the
reflection failure rather than silently switching the whole VR view.
