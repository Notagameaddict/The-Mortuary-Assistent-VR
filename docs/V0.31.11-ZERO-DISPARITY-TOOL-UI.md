# v0.31.11 — Zero-disparity dual-eye tool HUD

v0.31.10 made the wall/cabinet disappearance worse when the UI quad was moved
closer. That rules out ordinary virtual-distance tuning as the right fix.

The likely problem is binocular rivalry:

- one OpenXR quad was visible to both eyes;
- because the quad had finite depth, its left/right edges appeared at
  different angular positions in each eye;
- near walls/cabinets introduce strong stereo depth cues;
- the brain can then partially suppress or fuse the UI incorrectly;
- the unmatched edge can look like a black/blue strip, especially on one side.

v0.31.11 replaces the single BOTH-eyes quad with two eye-specific quads:

```text
Projection world
+ LEFT-only UI quad at X = -0.032 m
+ RIGHT-only UI quad at X = +0.032 m
```

Both use the same texture and crop. Because each quad is centered on its own
eye, corresponding UI pixels have approximately zero disparity. The menu now
behaves like a head-locked HUD rather than a finite-depth panel.

This should address both:

- the persistent right-side black/blue strip;
- the menu seeming to disappear into nearby walls/cabinets.

The v0.31.10 crop is intentionally kept unchanged so this test isolates the
stereo-composition change.
